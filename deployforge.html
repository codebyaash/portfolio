DeployForge

A simulation-first infrastructure deployment control plane that demonstrates enterprise cloud workflows without risky live provisioning.

The problem

Live infrastructure platforms are expensive and unsafe to demonstrate. The project still needed to prove desired-state planning, policy enforcement, drift awareness, cost visibility, history and rollback judgment.

Constraint: preserve realistic control-plane behavior while making demos deterministic, safe and free.

The solution

Users upload an IaC template, review parsed resources and proposed changes, run policy validation, simulate pipeline stages, and persist a new environment snapshot.

Upload → Parse → Validate → Compare state → Plan → Policy checks → Simulate → Persist → Graph · Cost · History · Rollback

Engineering evidence

Testing scope22 backend tests

Coverage includes auth, organization isolation, validation, template parsing, planning, policy violations, deployment history, drift and rollback.

API surface18 application routes

Auth, profile, projects, templates, planning, deployments, resources, cost estimation and rollback are represented in the control-plane API.

Security controlsJWT + ownership

Hashed credentials, JWT-protected routes, organization isolation, constrained CORS and startup rejection of unsafe production defaults.

Reliability observationSnapshot rollback

Desired state is compared with the latest stored deployment; rollback restores a previous resource snapshot without live cloud mutations.

Architecture trade-offSimulation over provisioning

Deterministic, free demonstrations improve safety and repeatability, but provider-specific apply behavior remains outside the current boundary.

CI/CD checks4 delivery gates

GitHub Actions runs an Alembic migration smoke test, pytest, the production frontend build, and TypeScript checking.
